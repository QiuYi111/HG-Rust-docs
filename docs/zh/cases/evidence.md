# 运行证据

四个教程里的流程都实际跑过。这里把结果放在教程之后，方便你先学会怎么搭，再看它是否经得起变化、失败和恢复。

## 四个案例各自证明了什么

| 案例 | 运行中检查的事情 | 观察到的结果 |
|---|---|---|
| Learning Helper | 三份资料分别整理，Word 公式存在，渲染页面可读，只改 Expansion 时其他两份不变 | 基准 10 次工作，未变重跑 10 次，改单份资料后 15 次。五次 live 耗时 33.910 到 46.635 秒 |
| Acquired Podcast | 六个受限研究方向、补充研究、三幕脚本、两份制作单、取消后恢复 | 初始并发上限 3，观察到最多 3 路重叠。五次 live 都保留了取消前完成的六份研究结果，耗时 45.056 到 69.804 秒 |
| Harness Lifecycle | 过期回答被拒绝、案例角色检查拒绝越权请求、协调 Agent 和执行 Agent 完成一轮，并生成 Git 证据包 | 五次 live 都完成一轮，基准 14 次工作并生成一个 Git 证据包提交，耗时 55.498 到 88.272 秒 |
| CAD Release | KiCad、ngspice、LibreOffice、三类有限范围检查、展示文件局部修复和 G6 响应门 | 五次 live 都保持 11 个上游结果不变，耗时 18.572 到 32.619 秒 |

## 共同的内核检查

独立的内核回归测试和案例压力运行共同验证了几项基础行为。下面这些能力不是说每个案例都单独覆盖了全部细节。

- 子进程的标准输出和错误输出同时读取，长输出不会把流程卡住。
- 取消和超时会结束整个 Unix 进程组，子进程不会留在后台继续跑。
- 失败的工作可以重试，已经提交的结果不会被重复覆盖。
- 取消后恢复会释放旧占用，新的运行不必等待租约自然过期。
- 文件、目录和 Git 项目都会按内容保存版本，工作区被改动后可以恢复。
- 明确设置网络限制时，未允许的主机、重定向和私网解析会被拒绝。
- 每次案例运行都会生成并通过 `hg.real-world-report/v1` 格式检查的报告。

HG-Rust 的完整验证命令如下。

```bash
make verify
make verify-ai
```

本次结果是产品测试全部通过，Harness 检查 65/65 通过。公开案例的报告文件来自运行时临时目录，网站保留这里的汇总和复现实步骤，没有把临时文件伪装成已归档的独立报告。

## 这些数字应该怎样理解

五次运行是当前的观察样本。它们说明流程确实跑过，不能直接当作长期性能承诺。正式时长、Token 和成本预算还要经过单独的校准。CAD 案例也只证明交付流程和证据链，不能替代制造、电气、机械和安全认证。
